UX / Front-End Case Study

M&M Kanban Tabule

A cold-calling & lead-acquisition kanban CRM, built from Figma design tokens to a working prototype

Project Overview

  • Kanban-based CRM prototype for a real estate agency (MM reality)
  • Module: Obvolávání — cold-calling & property-acquisition workflow for agents
  • Built as a fully functional, clickable prototype rather than static mockups
  • Delivered as a self-contained HTML/CSS/JS app, later ported to a Next.js 14 project
  • Design system sourced directly from the team's Figma file and implemented to spec

Project Summary

  • Four-column board: Contacts → Meetings → Call back → Acquired
  • Slide-out backlog drawer (75% viewport) with search, filter, sort, pagination
  • Lead-claiming flow with time-boxed reservation and countdown
  • Drag-and-drop across the board and from the backlog
  • Contact detail modal with inline scheduling / outcome actions
  • Light and dark mode, fully responsive down to mobile

Your Role and Duration

  • Role: product design and front-end implementation, AI-assisted (Claude as build partner)
  • Scope: data model, interaction design, Figma token extraction, styling, QA fixes
  • Duration: multi-session iterative build, delivered in incremental commits
  • Tools: Figma MCP (design context, variables), HTML/CSS/JS, Next.js, Playwright for QA

The Problem

  • Agents cold-call large volumes of leads with no shared visual tracking
  • Backlog can scale to tens of thousands of contacts — can't all live on one board
  • Multiple agents share the same lead pool, risking duplicate calls
  • No distinction existed between "today's work" and the full contact reservoir
  • No assembled UI yet — only a disconnected Figma component library

Goals

  • Fast, glanceable board that stays usable at any backlog size
  • Prevent double-calling via time-boxed lead reservation
  • Pixel-faithful translation of Figma tokens (color, type, spacing) into CSS
  • Clean, accessible interaction patterns for claiming, scheduling, and moving leads
  • Ship early, refine fast through iteration with the stakeholder

Design Process

1. Discovery & architecture

  • Evolved a single mockup into a real data model (contacts, statuses, sources)
  • Core insight: split the huge backlog pool from the small daily queue
  • Board shows only claimed leads; a slide-out drawer holds the full pool
  • Drawer designed for scale: search, filter, sort, and pagination instead of one long list

2. Component-driven design, sourced from Figma

  • Pulled real components node-by-node via Figma MCP: cards, section headers, page header, tooltips
  • Extracted actual Color and Text variables (Primary, Secondary, Gray scale) into CSS custom properties, not approximated
  • Corrected implementation against spec after review: icon choices, type scale, spacing

3. Core interaction design

  • Claim leads by multi-select + action button, or by drag-and-drop onto the board
  • Time-boxed reservation (1h / 8h / 24h by source) shown as a lock icon with countdown
  • Visual escalation near expiry, toast warning under 15 minutes, auto-release back to the pool after
  • Drag-and-drop across all columns, with matching column-level highlight on hover
  • Contact detail modal with inline action forms instead of page navigation

4. Visual refinement, feedback-driven

  • Reworked header, column, and card styling across several review passes
  • Removed UI that added noise once usage showed it wasn't needed — stats bar, redundant filters, per-card temperature badges
  • Fixed real usability bugs surfaced through testing: misaligned search icon caused by a leaking shared CSS class, a tooltip rendering off-viewport, a click-outside-to-close conflict with DOM re-render timing, drag-and-drop only moving one of several selected cards

5. Verification

  • Every change checked with automated headless-browser testing before shipping
  • Not just visual review — computed styles, DOM state, and simulated interactions
  • Kept the HTML prototype and the Next.js port in sync to avoid drift

6. Scaling & handoff

  • Expanded mock data to 180+ realistic contacts to stress-test the backlog UI at scale
  • Rebuilt the same product as a modular Next.js 14 app (components, lib, data layer) for handoff
  • Final polish pass: favicons, microcopy, mobile breakpoints, iOS-standard 44px tap targets
